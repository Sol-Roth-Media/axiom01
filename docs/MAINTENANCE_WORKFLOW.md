# Axiom01 Maintenance Workflow

## Canonical sources

| Purpose | Canonical location |
| --- | --- |
| Framework | `css/`, `js/`, `fonts/`, and `packages/` |
| Documentation site | `index.html`, `docs/`, `assets/`, `favicon/`, `css/`, `js/`, and `fonts/` |
| Public release facts | `release-info.json` |
| AI guidance | `AGENTS.md`, `llms.txt`, and `llms-full.txt` |

`dist/` is generated by `npm run build`, ignored by Git, and deployed as an artifact only. Never edit `dist/` or the `gh-pages` branch directly.

## Routine change

1. Update the canonical source and any directly affected documentation.
2. Run `npm test`.
3. Run `npm run build`.
4. Push to `main`. The **Publish documentation site** workflow rebuilds and deploys `dist/` to `gh-pages`.

## Release

1. Update `package.json`, `release-info.json`, and `CHANGELOG.md`.
2. Run `npm test` and `npm run build`.
3. Push a `v*.*.*` tag. The **Release Axiom01** workflow creates the GitHub release and publishes the npm package.

The release workflow does not publish the documentation site; normal pushes to `main` already do that. This keeps site updates independent of npm release timing.
