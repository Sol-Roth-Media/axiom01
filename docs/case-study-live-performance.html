1. The Problem: Why Utility Frameworks Fail on Stage

In high-pressure live performance environments, user interface software faces extreme constraints. Stacking 30+ utility classes per element creates unmaintainable DOM soup that is impossible to inspect in dark booths, slows down rapid attribute toggles, and triggers layout recalculation cascades that drop WebGL animation frames.

❌ Utility-First Anti-Pattern (Tailwind)

38 Classes 
<div class="flex flex-col bg-slate-900/80 backdrop-blur-md 
  border border-slate-700/50 rounded-lg p-4 shadow-xl 
  text-white font-mono hover:border-cyan-400">
  <div class="flex items-center justify-between pb-2 border-b">
    <span class="text-xs uppercase font-bold">Deck A</span>
    <span class="text-yellow-400 font-black text-lg">128.00</span>
  </div>
  <div class="mt-2 space-y-1">
    <h3 class="text-base font-bold truncate">Titan Awakening</h3>
    <p class="text-xs text-slate-400">Sol Roth</p>
  </div>
</div>

Difficult to inspect, high mutation cost, style fragmentation.

✅ Axiom01 Architecture

1 Class (Dc = 1) 
<article class="card deck" data-state="master">
  <header>
    <span>Deck A</span>
    <span>128.00 <small>BPM</small></span>
  </header>
  <main>
    <h4>Titan Awakening</h4>
    <p>Sol Roth • Extended Mix</p>
    <progress value="65" max="100"></progress>
  </main>
  <footer>
    <small>-01:42</small>
    <button class="primary sm">SYNC</button>
  </footer>
</article>

Clean semantic markup, child-order targeting, instant theme updates.

3. Official Upstream Modularization

To keep Axiom01 ultra-lightweight while supporting specialized creative domains, the framework has been split into:

  • @axiom01/core (~14KB minified): Mathematical tokens, semantic resets, typography, and standard layout/component primitives.
  • @axiom01/audio (~12KB minified): Pro-audio components, Camelot harmonic polar math, tactile MPC pads, and channel strips.
