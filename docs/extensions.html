ARCHITECTURE GUIDE

Axiom01 Extensions & Addons

How modular domain-specific extension packs bring specialized hardware, audio, and stage telemetry capabilities to Axiom01 while preserving a featherweight ~15KB core footprint.

1. Why Extensions? The Core vs. Domain Philosophy

Axiom01 is founded on the principle of Zero Bloat and minimal class density (Dc ≤ 1). The core framework provides general-purpose semantic primitives (typography, layout grids, buttons, cards, forms, tables, modals) for modern web applications, compressing down to ~15KB gzipped.

However, creative and technical industries have specialized interface requirements. For example, live concert systems, synthesizers, and DJ software require polar coordinate Camelot harmonic wheels, ballistic LED peak meters, 16-pad tactile matrices, and live stage teleprompter HUDs.

Bundling these niche components directly into Axiom01 Core would penalize general web developers with unneeded CSS and JavaScript bytes. Instead, Axiom01 utilizes a Modular Extension Pack architecture:

Axiom01 Core

Base semantic resets, design tokens, typography, standard components, and layout utilities. Zero external dependencies.

~15KB Gzipped · General Web

@axiom01/audio Extension

Pro-audio faders, LED peak meters, Camelot harmonic polar wheel, tactile MPC pad grids, and live teleprompter HUDs.

Modular Pack · Live Performance

2. Where Do Extensions Live? Monorepo Architecture

Axiom01 is maintained as an open-source monorepo hosted on GitHub at github.com/Sol-Roth-Media/axiom01.

Inside the repository, modular packages are organized under the packages/ directory:

axiom01/
├── css/
│   ├── axiom.css              # Unified build (Core + Components)
│   ├── axiom-core.css         # Lightweight standalone core
│   └── axiom-audio.css        # Pro-audio extension stylesheet
├── js/
│   ├── axiom.js               # Core component lifecycle engine
│   └── axiom-audio.js         # Audio runtime helpers (CamelotWheel, VUMeter)
└── packages/
    ├── core/                  # @axiom01/core standalone package
    │   ├── package.json
    │   └── css/
    └── audio/                 # @axiom01/audio standalone extension package
        ├── package.json
        ├── css/
        └── js/

3. How to Get & Install Extensions

All extensions are published and distributed through the official axiom01 package on the NPM registry, as well as via CDN and direct Git submodule inclusion.

Method A: Via NPM (Recommended)

Install the unified package in your project:

npm install axiom01

In your HTML or application bundler (Vite, Webpack, Next.js), import Core along with the Audio Extension:

<!-- Include Core Design System -->
<link rel="stylesheet" href="node_modules/axiom01/css/axiom.min.css">

<!-- Include Pro Audio Extension -->
<link rel="stylesheet" href="node_modules/axiom01/css/axiom-audio.min.css">

<!-- Optional: Include Audio JavaScript Helpers -->
<script type="module">
  import { CamelotWheel, VUMeter } from './node_modules/axiom01/js/axiom-audio.js';
  
  // Attach polar harmonic routing to Camelot wheel
  CamelotWheel.attach(document.querySelector('.wheel'), (key, details) => {
    console.log('Harmonic match:', key, details);
  });
</script>

Method B: Direct CDN / GitHub Pages

For zero-build environments, load directly from the official CDN:

<!-- Axiom01 Core CSS -->
<link rel="stylesheet" href="https://sol-roth-media.github.io/axiom01/css/axiom.min.css">

<!-- Pro Audio Extension Pack CSS -->
<link rel="stylesheet" href="https://sol-roth-media.github.io/axiom01/css/axiom-audio.min.css">

<!-- Audio Extension Runtime Helpers -->
<script src="https://sol-roth-media.github.io/axiom01/js/axiom-audio.js"></script>

4. Provenance: Battle-Tested in Live Concert Performance

The @axiom01/audio extension was not conceived as an abstract exercise. It was engineered and forged in production for the Sol Roth DJ Live Performance & Stage OS.

During live festival and club sets, latency is catastrophic. The live performance system drives:

  • Stage Prompter HUD: Auto-scrolling lyrics and live scene prompts locked to 16-bar musical phrasing.
  • Deck Telemetry: Real-time BPM tracking, Camelot key detection, and waveform meters across 4 active decks.
  • Master 3D Visualizer: GPU-accelerated Three.js WebGL rendering at a locked 60 FPS on monumental stage LED walls.
  • Multi-Window Sync: Sub-millisecond state broadcasting across multiple screens and remote mobile VJ controllers.

5. Authoring Axiom01 Extensions: The Specification

Community and domain-specific extensions must adhere strictly to the Axiom01 Design Ethos:

  1. Minimal Class Density (Dc ≤ 1): Exactly one class on the component's root semantic element (e.g. <nav class="padgrid">, <section class="prompter">, <article class="card deck">).
  2. Native Semantic HTML: Style directly on native elements: <header>, <main>, <footer>, <button>, <progress>, <kbd>.
  3. Zero BEM & Zero Utility Classes: No axiom-* prefixes, no *-header or *-button suffixes, and zero utility chains.
  4. Custom Property Integration: Use the unified Axiom01 token namespace (--a-color-*, --a-space-*, --a-border-radius-*).
